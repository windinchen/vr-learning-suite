# VR 学习套件：PICO 学生端 + 网页老师端

## 一、目标
- 学生只戴 PICO：打开「VR 学习启动器」，看到被批准的应用，点击进入；不在允许范围的应用是灰的，并被挡在门外。
- 老师只开网页：登记设备、开/关某个应用能不能跑、限每日时长、看每个学生今天用了多久、需要时一键锁定设备。
- 上课时才把人跟机器对上：**学生不和头显绑定**。老师开一节课，当堂指定「谁用哪台、这节课跑哪些应用」，
  网页上能实时看到每台头显的画面，用出来的时长自动算到那个学生头上；下课记录永久留着，换人只影响之后的记录。
- 所有「能不能跑」「跑了多久」由后台说了算，头显断网时按最后一次策略继续执行，联网后补报时长。

## 二、组成
| 模块 | 位置 | 技术 | 说明 |
| --- | --- | --- | --- |
| PICO 学生端 | `pico/` | Unity 2022.3.62f3 + OpenXR，Mono/ARM64 | 中文启动器：应用卡片、策略执行、时长采集与补报、课堂横幅与画面回传、锁定页、射线交互 |
| 后台服务 | `server/` | Node 26 + 内置 `node:sqlite`（零第三方依赖） | 设备/学生/应用/策略/课堂/画面转发/时长/报表/审计 |
| 老师网页 | `server/web/` | 原生 HTML/CSS/ES Module，免构建 | 总览、设备、**上课（画面墙）**、**头显应用（逐台扫描 + 逐台策略）**、学生、应用与策略、时长报表、日志 |

## 三、数据模型（`server/data/suite.db`）
- `teachers` 老师账号（scrypt 口令 + `sessions` 令牌）
- `classes` 班级 → `students` 学生（`student_no`、状态）
- `devices` 头显（`serial` 唯一、token、状态 active/locked/disabled、最后心跳、电量、当前前台应用）——
  **不再存「这台属于哪个学生」**，`devices.student_id` / `students.bound_device_id` 只作历史列保留
- `apps` 可管理的应用（`package_name`、分类、是否上架）
- `policies` 开关策略：`scope` = global / class / student / device，含 `allowed`、`daily_minutes`、`window_start/window_end`
- `usage_events` 时长流水（`started_at/ended_at/seconds`，`batch_id` 幂等）
- `heartbeats` 心跳、`commands` 下发指令（lock/unlock/restart/scan）、`audit_logs` 操作留痕
- `device_apps` 头显扫描回来的**应用清单**（`device_id` + `package_name` 唯一，含中文名、版本、是否 VR、是否系统应用、
  `installed`、`launch_count`、`last_seen`）——「这台头显到底装了什么」的账本
- `violations` 越权记录（清单外的应用被打开过，谁、什么时候、包名）
- `lessons` 一节课（`title`、`class_id`、`teacher_id`、`status` active/ended、`started_at/ended_at`、备注、整节课的应用白名单 `app_keys`）
- `lesson_devices` 这节课里的每台头显（`lesson_id` + `device_id` 唯一）：`student_id` 是**当堂**指定的使用者，
  `app_keys` 是这台单独收窄的清单（空 = 跟整节课一致）
- `device_screens` 每台头显最新一帧画面的元数据（`device_id` 主键、`ts/bytes/width/height`），图片本身落在 `server/data/screens/device-<id>.jpg`
- 迁移列：`usage_events.lesson_id` / `violations.lesson_id`（这条记录发生在哪节课，配合 `student_id` 就是「谁在哪节课用了什么」）
- 迁移列：`devices.app_mode`（`allowlist` 白名单 / `open` 只统计不拦）、`apps.source`（manual 老师录入 / device 头显发现）、
  `apps.managed`（0 = 已移出清单，manifest 不再下发）

## 四、策略计算（端上与服务端同一套规则）
优先级 `device > student > class > global`，取到第一条显式配置；未配置则跟随 `apps.enabled`。
再依次判定：设备是否 `locked/disabled` → 是否在允许时段 → 今日累计是否超过 `daily_minutes`，任一不过就给出 `allowed=false` 与中文原因（例如「今日 40 分钟已用完」「不在允许时段 14:00-16:00」）。

上课再加一层（`server/src/lesson.js`）：这台头显在上课的话，取 `lesson_devices.app_keys`（没有就取整节课的 `lessons.app_keys`）
当白名单，清单外的应用 `allowed=false`、原因写成「《课程名》这节课没安排这个应用」，判断仍走同一套优先级，端上离线也照此执行。

头显应用再加一层：`apps.managed=0` 的应用直接不下发；设备 `app_mode=allowlist` 时，**清单外的应用一律不许打开**，
客户端会把它踢回桌面并上报越权。白名单模式下拦人很小心——同一个包名要**连续两轮**都排在最前面才动手，
避免应用启动瞬间抓到过渡界面就误杀。

## 五、接口（`/api/v1`）
学生端（`X-Device-Token`）
- `POST /devices/enroll` 首次登记，返回设备 token
- `GET  /manifest` 拉应用清单 + 策略 + 剩余时长 + 待执行指令，并带回 `rev`（后台改动版本号）
- `POST /devices/heartbeat` 心跳（电量/前台应用/Wi-Fi），带回指令 + `rev`。
  头显拿 `rev` 和手里那份清单的版本号一比，就知道老师刚改过东西，立刻重拉清单——
  详见第十五节后面那段「老师改完多久到学生」
- `POST /usage/batch` 批量上报时长，重复 `batch_id` 自动去重
- `POST /devices/apps/sync` 上报这台头显扫到的应用清单；后台没登记过的第三方应用自动进目录（`source=device`、`enabled=0` 等老师确认），
  这次没报上来的置 `installed=0`，返回逐应用的 `deviceAllowed`/`deviceDailyMinutes`
- `POST /devices/violation` 上报一次越权打开（清单外应用被点开）
- `POST /devices/screen` **body 就是一帧图片二进制**（JPEG/PNG 都收），靠 `X-Device-Token` 认设备，
  `X-Frame-Width` / `X-Frame-Height` / `X-Frame-App` 三个头带元数据；顺手当一次心跳刷 `last_seen`，
  返回后台要求的 `intervalMs`。**HTTP 头只能是 ASCII**，所以 `X-Frame-App` 放包名而不是应用中文名

老师端（Cookie 会话）
- `POST /auth/login`、`POST /auth/logout`、`GET /me`
- `GET /dashboard` 今日在线、活跃学生、总时长、Top 应用、异常清单
- `GET/PATCH /devices/:id`、`POST /devices/:id/command`
- `GET/POST/PATCH/DELETE /students`（`POST /students/bulk` 整贴名单导入）、`/classes`、`/apps`
  ——学生改学号/转班、班级改名/删班都在这里，见第十七节
- `GET/PUT /policies`、`GET /reports/usage`、`GET /audit`
- `GET /devices/:id/apps` 某台头显的应用清单 + 逐应用管控状态 + 越权记录
- `PATCH /devices/:id` 收 `appMode`（白名单/只统计）；`PATCH /apps/:id` 收 `managed`（移出清单/重新纳入）
- `GET /violations` 越权记录列表；`POST /devices/:id/command` 支持 `scan`（让头显重新扫描）、
  `restart`（清令牌重新登记）、`message`（带句话，`{text}` 会打上头显首页横幅 45 秒）
- `POST /devices/:id/backend` 把后台自己的地址推给这台头显（`{host?,port?}` 可省，默认照上次问到它的地址），
  收编时自动做一次；回 `{ok, serverBaseUrl, reason, applied}`，推不过去也是 HTTP 200 + 中文 `reason`
- `PUT /policies` 回 `{ok, notice}`：应用刚允许、但正在上的那节课把清单限死了没带上它，`notice` 直接说「去上课页勾进这节课」
  （判定和 `buildManifest` 同一份清单：`lesson_devices.app_keys ?? lessons.app_keys`）
- `GET /devices` 每台多给 `lastHeartbeatAt` / `offlineReason` / `probePort`：离线到底是「不知道后台在哪」还是「睡了」，界面不用再猜

上课（老师端 Cookie 会话）
- `GET  /lessons?limit=` 上课记录（含每台头显数、学生数、总时长）
- `GET  /lessons/active` 当前正在上的那节；`GET /lessons/:id` 课堂详情（每台头显的在线/电量/使用者/时长/画面 + `summary[]` 学生×头显×应用 + `totals`）
- `POST /lessons` 开课 `{title, classId|null, note, deviceIds[], appKeys[]}`；`deviceIds` 不能为空
- `POST /lessons/:id/assign` 当堂指定 `{deviceId, studentId|null}`；`POST /lessons/:id/devices` 中途加一台
- `POST /lessons/:id/apps` 改这节课能跑的应用 `{appKeys[], deviceId?}`（不给 `deviceId` 就是整节课，给了就只改那台；空数组 = 恢复跟后台默认）
- `POST /lessons/:id/end` 下课（撤回当堂分配，记录与画面保留）
- `GET  /devices/:id/screen` 拿到那台头显最新一帧图片（二进制，未登录 401，从没传过 404）
- `PATCH /devices/:id` 收到 `studentId` 直接 400「设备不再绑定学生，请到「上课」页当堂指定谁用哪台」

免登录（头显自己找后台用）
- `GET /hello` 后台自报家门：`{product:"vr-suite", name, version, serverTime, baseUrl}`。
  头显「自动找后台」挨个地址敲的就是这一句——**认 `product` 这个暗号，不认端口号**，
  8787 上跑着别的服务时不会被错当成后台；`baseUrl` 是后台对外报的地址，头显照抄它比自己拼 IP 稳

打包链路上另外踩到并已修掉的三点：

- **锁屏遮罩徽标压字**：徽标改用卡片顶部定位（`LauncherUI.BuildLockLayer`），不再挡住两行提示。

### PICO 启动器（Unity）
```bash
bash scripts/unity.sh check   # C# 编译体检（headless）
bash scripts/unity.sh setup   # 生成 Assets/Scenes/Launcher.unity + 写 Android 打包参数
bash scripts/unity.sh play    # 进播放模式，编辑器开着，可以用鼠标点着试
bash scripts/unity.sh shots   # 自动抓 5 张界面图到 Build/Screenshots/，抓完自动退出
bash scripts/unity.sh verify  # 无头自检：扫描→清单→界面→拦截→按 IP 问一句，不开窗口，约 2 分钟
 node scripts/api-test.mjs     # 只跑后台接口自检（几秒钟，条数以脚本打印的那行为准）
node scripts/mock-pico.mjs      # 模拟一台头显上线：报应用清单、心跳、时长，收到 scan 指令会重扫
bash scripts/unity.sh apk     # 打 APK → Build/Android/VR-Launcher.apk
bash scripts/install-tuanjie-android.sh   # 给团结引擎补 Android Build Support + OpenJDK 17（免 sudo，约 920MB + 107MB）
node scripts/apk-check.mjs    # 拆开 APK 搜标记，确认包里到底有没有 8790 问话口（--strict 缺了就非 0 退出）
```
编辑器里的默认后台地址是 `http://127.0.0.1:8787`，设备序列号固定用 `PICO-4U-A1B2C3`（后台种子数据里的「VR 头显 01」），
所以 `bash scripts/dev.sh` + `bash scripts/unity.sh play` 就能看到真数据；在网页「上课」页把这台拉进课堂并指定使用者，
启动器顶栏立刻变成「上课中《…》」，只留这节课安排的应用，并开始往后台回传画面。
真机则要在启动器「设置」里把地址改成机房电脑的局域网 IP。
启动器另外开着一个 **8790 问话口**：网页「PICO 设备 → 按 IP 找头显」可以让后台反过来敲它，
头显还没登记、甚至后台地址填错了都能被找出来收进后台（第十四节）。
「设置 → 本机信息卡」最后一行直接写着「网页里填 192.168.x.x:8790」，老师照抄就行，不用自己查 IP。

> **编辑器怎么找的**：先问工程自己——`scripts/unity.sh` 读 `pico/ProjectSettings/ProjectVersion.txt`，
> 版本号带 `t`（`2022.3.62t16`）或有 `m_TuanjieEditorVersion` 就是**团结引擎工程**，挑选顺序为
> `UNITY_EDITOR` → 团结引擎 `/Applications/Tuanjie/Tuanjie.app/Contents/MacOS/Tuanjie` → Unity Hub；
> 普通工程才把 Unity Hub 排在前面。为什么要看声明：`Packages/manifest.json` 里
> `com.unity.xr.interaction.toolkit` / `com.unity.xr.openxr` 是 `-t2` 版，只有团结引擎的包源里有，
> 拿 Hub 装的正版 Unity 开这个工程必定停在 `Project has invalid dependencies`。
> 选错时脚本**当场停下并给出可抄的命令**，不再跑几分钟才失败；显式给了 `UNITY_EDITOR` 视作有意为之，只提醒不拦。
> 每次开跑都打印「工程声明编辑器：… ｜实际用：…（版本）」，版本和声明不一致再加一行提醒。
> 日志诊断同理：失败时先挑关键行，挑不到就倒出日志尾巴（查日志一律 `rg -a`，日志里夹着二进制字节，
> 不加 `-a` 会一声不响地"查不到"）。
> 只装了 macOS 模块的编辑器（比如只有团结引擎、没装 Android Build Support）照样能 `check` / `verify`，
> 但 `apk` 会直接停下并提示去装 Android 模块，不会跑到一半才失败。

> 画面回传的节奏由后台环境变量 `SCREEN_INTERVAL_MS` 决定（默认 1500 毫秒，最低 400），
> 下发在 `GET /manifest` 的 `lesson.screen.intervalMs` 里，头显按它抓帧上传，`POST /devices/screen` 的响应也会带回来纠偏。
> 模拟头显要跳过画面回传就加 `--no-screen`。

> **为什么要镜像构建**：Android 的 Gradle/aapt 拒绝非 ASCII 工程路径，而本工作区在 `~/Desktop/项目任务/` 下。
> `unity.sh apk` 会把 `Assets`/`Packages`/`ProjectSettings` 同步到 `~/.cache/vr-pico-build/pico`（纯英文）再构建，
> 打完把 APK 拷回 `Build/Android/`。`pico/` 始终是工作区里唯一的真源码，镜像目录可以随时删掉重建。
> 直接双击 `pico/` 打开编辑器做 UI 调试没问题，只有打 APK 走镜像。

`ConfigureToolchain()` 结尾会打印 JDK 来源、Gradle 路径各一行——配错了看日志一眼就知道，不用再猜哪个键没生效。

`install-tuanjie-android.sh` 的下载缓存默认在 `/tmp/tuanjie_dl`（安装包 + 展开目录，装完一共 ~4.7G）。
展开目录拷完就没用了，删掉只留 `.pkg`/`.zip` 也就 1G；换地方用 `TJ_DL_DIR=~/Downloads/tuanjie bash scripts/install-tuanjie-android.sh`，

打包配置是 **IL2CPP + ARM64**（PICO 是 arm64 单机）。几个坑记一下：
- Unity 2022.3 的 **Mono 后端拒绝「ARM64 单架构」**，会报「Target architecture not specified」，只能连 ARMv7 一起勾；
  IL2CPP + ARM64 才干净，但需要 NDK。
- **Android SDK 组件版本要够新**：`build-tools;34.0.0` + `platforms;android-34` + `cmdline-tools ≥ 12`，
  只有 33 的话构建阶段会报「Failed to update Android SDK」。
- **`targetSdkVersion` 只能到 33**：Unity 2022.3 自带 Gradle 模板是 AGP 7.1.2，设 34 会在 Gradle 阶段报
  「use a newer Android Gradle Plugin that has been tested with compileSdk = 34」。SDK 里装 34 仅用于通过组件检查。
- **团结引擎要 JDK 17，而 Android 模块包不含 JDK**：只装 `android` 模块会在**几秒内**失败并报
  `UnityException: JDK not found`（快得不像构建失败，容易误判成 Gradle 的锅）。脚本默认连 `android-open-jdk` 一起装；
  这和「Unity 2022.3 要用 JDK 11」不冲突——那条只对正版 Unity 成立。
- 工作区路径含中文，所以 APK 走英文镜像构建（见上文「为什么要镜像构建」）。

## 九、头显应用管控（头显扫自己装了啥，老师在 PC 后台逐台配策略）
思路：启动器不是「老师凭记忆录包名」，而是**头显自己把装了什么报回来**，老师在这份真实清单上打勾。

### 客户端怎么扫
- 真机：`pico/Assets/Scripts/Integration/AndroidApps.cs` 的 `ScanInstalled()` 走 Android `PackageManager`，
  按 LAUNCHER 意图 + VR 类别（`com.oculus.intent.category.VR` / `info.android.intent.category.VR` / `com.pico.intent.category.VR`）
  列出可启动应用，取中文名、版本号、安装时间，并用 `FLAG_SYSTEM` 区分系统应用；自身与启动器不纳入管控。
- PC 模拟：`pico/Assets/Scripts/Core/LocalAppScanner.cs` 读
  `~/Library/Application Support/school/VR 学习启动器/local-apps.json`，
  文件不存在时自动生成 7 条演示应用；改完这个 JSON，在界面上点「重新扫描」立刻生效。
  底栏「本机应用 → 模拟打开」可以直接演示拦截，不用真装 App。
- 每 30 轮心跳自动重扫一次；本机清单有变化就立刻 `POST /devices/apps/sync` 并重新拉一次 manifest。
- 没有真机也没有编辑器时，`node scripts/mock-pico.mjs` 模拟的头显也会上报一份应用清单，
  并且在收到 `scan` 指令时重扫重报，网页上点「扫描这台头显」立刻能看到反馈。

### 老师在 PC 后台做什么（网页「头显应用」页）
`server/web/js/app.js` 的「头显应用」页（左侧第 4 项），整页围绕**一台选定的头显**展开：
- **选一台头显**：每台一张卡片，写着在线状态、已装几个、今日越权、最近扫描时间、这节课谁在用；点卡片就切过去。
- **这台装了哪些应用**：五张统计卡（清单里几个 / 这台已装 / 清单里但没装 / 现在不许跑 / 今日越权），
  一行状态（在线·电量·最后心跳·正在跑哪个应用·这节课使用者），
  以及「🔄 扫描这台头显」（下发 `scan` 指令）和「刷新策略」（下发 `refresh`）。头显没扫过时这里直接说「还没扫描过，点扫描」。
- **应用策略**：`全部 / 已装 / 没装 / 被禁止` 四个筛选 + 名称包名搜索（不重新请求，纯本地过滤，
  头显上装了上百个应用也不卡），逐行改**这台**的「是否允许 / 每日上限」，
  两条批量按钮把当前筛出来的已装应用一次性全部允许或全部禁止。
  以前还有第五个筛选「系统应用」，现在拿掉了：系统应用按规矩压根不进管理清单，
  留着它永远是 0，点一下反而把整张表筛空，看着像坏了。
- **清单外的应用**：头显扫到但没进管理清单的（多为系统应用或学生自己装的），一键「纳入管理」。
- **越权打开记录**：白名单模式下被拦回桌面的回执，带时间与当堂使用者。
- **这台的应用清单从哪来**：只认头显自己扫的。后台不再提供「手工往这台补一条应用」的入口——
  手工编出来的包名跟头显实际装的东西对不上，白名单就会拿一份假清单去拦真应用。
  没扫过的行一律标「这台头显没扫到」，点上面「🔄 扫描这台头显」让它重扫才是正路；
  行末按钮按**这台装没装**分派，别再拿一个按钮干两件事：
  `installState=installed` 给「删扫描记录」（`DELETE /devices/:id/apps/:pkg`，只删这条扫描记录，头显下次重扫照实报上来）；
  `missing` / `unknown` 给「从清单删除」（`DELETE /apps/:id`，把它从管理清单里去掉，策略和各台的扫描记录一起清）。
  以前不管装没装都发「删扫描记录」，而这台压根没有那条记录 → 后台 404 → async 回调里没人接 → 老师看见的就是「点了没反应」。
策略优先级：`这台头显的专属策略 > 班级 > 全局默认`，写完全屏刷新，头显下次心跳（约 10 秒）生效。
`PUT /policies` 里「跟随默认 + 不限时长 + 不限时段」等于**删掉这条专属策略**，不会在策略列表里留一条全空的记录。
设备页有「已装 N 个」入口和越权徽标；总览有「待确认新应用」「今日越权」两张卡。

**「应用与策略」这张表 = 头显实际装着的东西，不是后台自己攒的目录。** 整页**没有新增应用的表单**，
原来的「来源」列换成了**「哪几台头显装着」**：由 `GET /apps` 返回的 `installedOn[]`（`{id,name,version,lastScanAt}`）
现算，每行直接列出「模拟头显 1.0.0｜最近扫到 3 分钟前」，后台不另存一份口径（`installedDevices` 就是它的条数）。
表头三个入口：「让 N 台在线头显重新扫描」（给每台在线头显各下发一条 `scan`）、
「也显示头显上已经没有的 N 个」开关（`state.apps.showGone`），以及策略下拉——**下拉里只放现在看得见的这些应用**，
免得给一个头显上早就没有的应用配完策略，谁都不执行。
默认只列头显上真装着的（`installedDevices > 0`）；上过架但头显已经没有的收进开关里，标「头显上没有了」；
**从没上架过、头显又报不上来的应用直接不留**（`applyDeviceApps()` 收尾自动退场，见第十节那条 bug）。
`POST /apps`、`POST /devices/:id/apps` 两个接口留着（自检与脚本兜底用），网页上不再摆入口。

### 无头自检
`bash scripts/unity.sh verify` 会在 batchmode 里走完五步并打印结论，不依赖显示器：
读本机应用 → 校对后台清单与 `installState`（顺带打印课堂状态与画面抓帧结果）→ 校验「本机应用」页行数 →
打开清单外应用确认被拦下、越权计数 +1 → 自己敲本机 `127.0.0.1:8790/v1/identity`，
验问话口答的序列号就是这台、答复里带着应用清单、乱敲别的路径不漏清单。

## 十、自检（`bash scripts/test.sh` + `bash scripts/web-test.sh`）
仓库没引测试框架，三套自检都是纯脚本，跑完打印中文结论、失败时退出码非 0。

> **别拿真库当测试场**：`bash scripts/test.sh`（接口 / 网页两段）默认自己起一个一次性后台 + 临时库——
> 端口 `SELFTEST_PORT`（默认 8788），库在 `$TMPDIR/vr-selftest.XXXXXX/suite.db`，跑完停服务、删目录。
> 自检会造临时头显、改应用上下架、末尾还点一次「清空数据」，直接拿 `server/data/suite.db` 跑，
> 老师真正的策略、时长和扫描记录就都没了。跑挂了就把临时目录留着方便看 `server.log`。
> 要对着指定后台跑（真机联调）就给 `BASE=...`，那时它会照实改那个库。
> 上次被 Ctrl+C 打断留下的遗留后台，下次开跑先按 `$TMPDIR/vr-selftest-<端口>.pid` 停掉，不会自己占自己的端口。
> `unity` 那段是**真客户端**，它写死了连 8787，所以那段不走临时库。

- `scripts/api-test.mjs`——后台接口全链路 **166 条断言**（条数会随功能加，以脚本打印的「断言 N 条」为准）：登录与错误口令、设备令牌校验、登记、扫描上报、
  自动发现未登记应用、卸载检测、逐台禁止/每日上限/移出清单/重新纳入、白名单与自由运行切换、
  越权留痕、`scan` 指令下发与确认、心跳只数真正的「换应用」、时长上报与 `batch_id` 幂等、报表、总览指标、
  设备/学生/应用/头显应用的增删与错误路径、清空数据不掉登录，一整轮课堂流程
  （开课 → 当堂指定 → 课堂清单把别的应用挡在门外 → 画面上传与取回 → 时长算到学生头上 → 换人/加台/下课的错误路径），
  以及一整条「按 IP 找头显」链路（脚本自己起一个假问话口 → 问到 → 扫网段捞出 → 收编入库 → 重复收编不重复建）。
  用一台固定的「自检专用头显（可忽略）」跑，开头会先扫掉上次残留的 `PICO-TEST-*` 头显、替老师收掉没下课的课，
  所以**连着跑两遍结果一样**（已实测连跑两遍全绿）。
  开头还有一步「自检前的准备」：要用的三个应用如果被老师下架过，就临时上架、跑完原样还回去——
  否则那几条「课堂清单把别的应用挡在门外」的断言其实是在测「下架」，老师点没点上架都会影响结论。
  收尾时额外断言两件事：老师原本下架的应用确实恢复成下架；清空数据**一个应用都不删**，
  自检乱入的那几个（《偷偷装的游戏》《自检体测教练》+ 本轮的两个临时包）由自检自己删干净。
  还有一整步「应用跟着头显的实际清单退场」：扫来两个新应用（断言自动进目录、先不上架、
  `installedOn` 当场记上装在哪台和版本号）→ 把其中一个上架 → 再扫一遍两个都卸载了 →
  断言没上架过的那个跟着退场（`retired`）、上过架的那个留在目录里且 `installedDevices=0`、
  这台头显那条 `installState=missing` 的记录还在（报表要能对上账）。
  另外「哪几台头显装着」的口径也钉住了：`installedOn` 里必须有这台自检头显、`installedDevices` 等于它的条数、
  带得上最近扫到的时间，而这台没报上来的应用不会混进 `installedOn`。
- `scripts/web-test.sh`——浏览器自检 **57 条断言**（同上，以脚本打印为准）：先让 `mock-pico` 上一轮班把应用清单报上来，再真开一个 Chromium
  （用系统里 Playwright 已缓存的浏览器，驱动装在 `.webtest/`，后台依旧零第三方依赖）把八张页面逐张点开、
  在「头显应用」页验设备卡片数量与后台一致、统计口径一致、搜索能过滤、「已装」筛选跟后台口径一致、
  筛选条里不再有那个永远筛不出东西的「系统应用」（系统应用压根不进管理清单，它们得列在「清单外的应用」面板里）、
  批量允许/禁止真的写成 device 级策略且能改回「跟随默认」、点「扫描这台头显」指令入队，
  「没扫过的头显」那条不再看数据脸色：自检自己登记一台 `PICO-TEST-WEBIDLE`、断言页面写着「还没扫描过应用」且
  「这台已装」是 0，用完删掉并断言卡片消失（以前写成 `if (idle >= 0)`，没有样本就等于没测）；
  扫描指令的断言也改成直接读 `GET /devices` 里的 `pendingCommands`，跟页面同一个口径，不再靠字符串碰运气。

  验问到的是这台、收编后设备列表里就出现它，同时抓页面图。
  「8790 上没人监听」这一坑也钉住了：拿一个刚放开的空端口（`closedPort()`，已从 `api-test.mjs` 提到

  收编时顺手扫进来的《自检体测教练》（包名前缀 `com.selftest.`）也从应用目录删掉——
  自检不该在老师的应用清单里留个假应用，这条现在也写成了一条断言。
  还有一组「清单只能扫出来」的断言（8 条）：应用页再也找不到 `#app-form` / `#add-local-app` 两个手工录入表单，
  表头必须写「这张表是从哪来的｜头显实际装着什么，这里就列什么」，表头列必须是「哪几台头显装着」而**不再有「来源」**
  （直接读 `<thead>` 的单元格文本比对），一键重扫按钮和「也显示头显上已经没有的」开关必须在位，
  两页上讲清「清单从头显扫出来 / 只认头显自己扫的」的文案必须在。
  其中「默认只列头显上装着的应用」这条是拿页面标题上的数字和 `GET /apps` 现算的 `installedDevices > 0` 条数对的——
  口径不一致就红，而不是只看看文案。
  断言全部以接口返回的口径为准，所以数据怎么变都不会误报。
  这套自检抓出过一个真 bug：`isSystem` 定义在用例之后（TDZ），进页面直接 ReferenceError 白屏，`node --check` 查不出来。
- `scripts/unity.sh verify`——Unity 无头自检五步：读本机应用 → 校对后台清单与安装状态（附带打印课堂状态、
  被课堂规则挡住的应用数、画面抓帧结果）→ 「本机应用」页行数 →
  打开清单外应用确被拦回桌面且越权计数 +1。本机应用都在清单里时会临时加一个《拦截探针》应用，
  保证这一步每次都真的跑到，不会因为没有越权样本而静默跳过。
  最后一步自己敲本机 `127.0.0.1:8790/v1/identity`：验答的序列号就是这台、`apps[]` 里条数跟快照一致、
  敲 `/v1/nope` 只回 404 不漏清单——这条同时管着两件事：问话口真的绑得上（不是只绑回环的空壳），
  以及快照的 JSON 是合法 JSON 且中文应用名没把后台解析带崩。
  batchmode 没有真实渲染设备，抓帧那一步允许降级成「屏幕尺寸读不到」这类原因说明——断言的是**不抛异常、有明确结论**。

自检顺手抓出来并修掉的四个真 bug：
- `GET /reports/usage` 把 `URL` 对象直接当 `URLSearchParams` 传进去，接口 500，网页「时长报表」页一直在报错。
  已在 `server/src/server.js` 改成传 `ctx.url.searchParams`。
- 老师网页导航 id 是 `device-apps`，渲染函数键写成 `deviceApps`，点这一页直接白屏（这一页当年还叫「本机应用」，现在叫「头显应用」）
  （`RENDER[state.page] is not a function`）。已在 `server/web/js/app.js` 对齐。
- **「清空数据」把老师的应用清单一起删了**：`clearRunData()` 认定「`source='device'` 的应用 = 自检脏数据」，
  可自从「清单只能由头显扫出来」之后，真应用的 source 全是 `device`，老师点一次清空，整个应用目录就空了
  （接口自检跑完也是这个下场）。最终改成**清空数据一个应用都不删**（`server/src/reset.js` 里干脆去掉了
  `removedDiscoveredApps` 这个返回值）：应用目录是老师配的东西，不是跑出来的数据；
  自检塞进去的野应用谁塞的谁自己删（`scripts/api-test.mjs` 收尾负责）。
- **上一款的补丁漏了个更隐蔽的同类 bug**（这轮接口自检连跑第二遍才炸出来，一次红了 11 条）：
  「清单跟着头显走」的自动退场拿「没有任何 `installed=1` 记录」当「卸载了」，
  可「清空数据」正好会把全部 `device_apps` 抹掉、删头显也会带走它的记录——
  那时候证据是**「不知道」**而不是「卸载了」，于是清空之后的第一次同步把老师目录里所有 `device` 来源的应用全删了。
  已改成退场必须有**正面证据**：还得存在一条在册头显留下的 `installed=0` 记录才退
  （`server/src/api.js` 的 `applyDeviceApps()`，两条 `EXISTS`/`NOT EXISTS`），
  记录被清空时应用一律留着当「没扫过」，宁多留不误删。
- **「系统应用」筛选永远筛不出东西**：管理清单压根不收系统应用（`applyDeviceApps()` 就把它挡在门外），
  可「头显应用」页还摆着第五个筛选，点一下整张表被筛空，看着像页面坏了。已拿掉这个筛选条与对应的
  `data-system` / `isSystem` 分支，系统应用继续老老实实在「清单外的应用」面板里待着（`server/web/js/app.js`）。
  顺带把扫描收录应用的类别从「设备发现」改成「未分类」——「设备发现」跟这轮的「按 IP 找头显」撞名，
  摆在应用表里更让人分不清谁是谁（老库里已入库的由 `server/src/db.js` 一次性改过来）。

## 十二、头显端交互（学生用 · 鲜艳圆角卡片）
头显是学生手里唯一的那块屏，不用键盘、只有一对手柄，所以界面**全部在运行时用代码搭**（不依赖场景 / 预制体 / 字体资源，换机器就能跑）。
这一版按「给学生用」重排了五件事：**去掉硬边**（全圆角）、**一屏只说一句话**（首页做减法）、
**功能性的东西收进设置页**、**界面铺满整屏**、**导航只留一条**。

### 一屏的骨架（1280×840，World Space，摆在面前约 2 米，缩放按视锥算出来）
首页从上到下只剩三段——顶栏 → 一张横幅 → 应用卡两列 → 一条常驻导航；原来那排四张状态卡和三张筛选卡删掉了。
尺寸常量全部集中在 `pico/Assets/Scripts/UI/LauncherUI.cs:22`，改版只动这些数字：
`BarTop 22 / BarHeight 76 / BannerTop 118 / BannerHeight 148 / ListTop 288 / ListHeight 404 / NavTop 712 / NavHeight 96 / 应用卡 592×168（两列，间距 16）`。
弹层的尺寸不再各写各的，全部从导航那条推出来：`PanelLeft = Margin`、`PanelTop = 40`、`PanelWidth = ContentWidth`、
`PanelHeight = NavTop - PanelTop - 20`、`PageListHeight = PanelHeight - PageListTop - 28`、`PageCardWidth = (PanelInner - 24 - 18) / 2`。
这样弹层左右和顶栏、应用列表对成同一栏，**下沿永远停在导航条上方 20 像素**，卡片不会藏到导航底下；
卡片里左边文字列的宽度也是 `PageCardWidth - 240` 算出来的，以后改宽度不会让文字压到右侧胶囊上。

| 卡片 | 写什么 |
| --- | --- |
| 横幅（一张，色块即结论） | 大字「现在能跑 3 个应用」+ 小字「一共几个｜今天已跑多久｜《某某》只剩几分钟｜点一张卡片就能进」+ 我是谁 + 刷新清单 |
| 应用卡（592×168） | 分类色大图标块、名称、分类与装没装、时长进度条、「今天跑了 X 分钟｜还能跑 Y 分钟」，右侧状态胶囊 + 一个动作卡 |
| 导航卡（全局只有这一条） | 应用 / 我的时长 / 设置 三张页签 + 一条分隔线 + 「回桌面」动作卡，每张固定一支亮色，卡上带一行摘要（几个能跑 / 今天跑了多久 / 后台·权限·日志） |
| 弹层卡 | 顶部 3 张统计卡 + 可滚动卡片网格（时长卡、本机应用卡），换页走底部那条导航；**设置页另有本机应用卡、管控模式卡、后台地址卡、本机信息卡、权限卡、操作卡、日志卡** |
| 详情卡 | 6 张信息卡：现在能不能跑、为什么是这个结果、今日已用、还能跑多久、允许时段、这台装没装，底部才是动作卡 |
| 确认卡 | 换后台地址、清令牌、退出之前先问一句 |
| 锁定卡 | 老师锁定这台设备时整屏就一张卡：为什么被锁、怎么解开、能不能重试 |

### 界面铺满整屏（不再是一块飘在黑边里的小面板）
以前画布缩放写死 `0.0015`，实测只占视野约 52%，学生看到的是一块飘在黑色里的小面板。
现在 `LauncherUI.cs` 的 `FitCanvasToView()` 按相机视锥现算：`min(可见高 / 840, 可见高 × aspect / 1280) × FillRatio`，
取竖、横里更紧的那个，所以永远不会切掉内容；`FillRatio = 0.98` 是唯一调松紧的旋钮（1.0 就是完全贴边）。
视野比例会变（XR 起来、编辑器拖窗口），`Update()` 里发现 `uiCamera.aspect` 变了就重新铺一次。
无头抓图那边 `pico/Assets/Scripts/Editor/Automation.cs:101` 在进播放模式时把 `camera.aspect` 调成抓帧画幅的比例，
否则相机还停在 Game 视图的比例上，算出来的铺满值偏小，出来的图四周又是一圈黑边（看着像没改）。

### 不硬了：圆角是代码生成的
`pico/Assets/Scripts/UI/LauncherUI.Kit.cs` 里 `Rounded(radius)` 用圆角矩形的 SDF 现场生成一张九宫格精灵
（`sdRoundBox` 算到边界的距离，末尾必须减回半径，少减这一项整张精灵就只有中心几像素不透明，卡片会被画成中间一条亮带），
`Sprite.Create(..., SpriteMeshType.FullRect, border=R)` + `Image.type = Sliced`，所有卡片、按钮、胶囊、进度条都走
`AddImage(parent, name, color, radius)`；四角不参与拉伸，卡片拉多大多小圆角都不变形。
半径不用手写死：`Place` / `PlaceRight` / `PlaceBar` / `PlaceLine` / `Center` 排完版都会调 `FitRadius`，
九宫格两片圆角之和超过元素短边就自动降一档（留 ≥2 像素可拉伸区）——矮元素圆角太大时 Unity 会把中间算成负数、整块塌成一条细线。
左侧色条和底部高亮线也跟着圆角化：`PlaceBar(x=14, width=12, inset=18)`、`PlaceLine(h=4, inset=20, lift=8)`，
色条自己也是一颗胶囊，不会从弧形角上戳出去；卡片内的文字一律从 x≥32 起排，给色条让位。
文字行距固定 1.0（`AddText`）：uGUI 单行占位高约等于字号×1.16，行距再放到 1.16 会让大字比文本框还高，底部直接被 Truncate 切掉。

### 颜色就是导航
调色板在 `pico/Assets/Scripts/UI/LauncherUI.cs:57`：五支亮色 `Sky #35D0FF / Mint #7BE495 / Amber #FFB347 / Coral #FF7EA6 / Grape #A78BFF`，
`Accent=Sky`、`Good=Mint`、`Warn=Amber`、`Bad=Coral` 只是别名；亮底上的字统一用深色 `InkDark`，比白字更清楚。
- **横幅底色 = 状态色**：蓝=正在跑、绿=时间宽裕、橙=快用完、粉=都跑不了、紫=还没清单，学生不用读小字；
- **页签定色**：应用=蓝、我的时长=绿、设置=橙（本机应用是设置页的子页，用紫色但不占页签）；当前页那张底色按本支色染到 40%，标题也染同一支；
- **应用卡**按分类染色（图标块涂满分类色 + 卡片底色染 14%），动作卡只在「真能进」时才涂满饱和色；
- 状态从文字改成**胶囊**：`能跑` / `只剩 N 分` / `今天用完啦` / `不在时段` / `老师没开` / `没装` / `正在跑`。

### 导航只有一条：换页、返回、退出
以前首页一套页签、弹层里又一套页签，弹层蒙层把首页那套压暗又没对齐，叠出两层重影，学生分不清自己点的是哪一套。
现在**全局只有 `BuildNavLayer()` 建的那一条**，它单独一层、建在弹层之后（`LauncherUI.cs` Awake 的顺序），
所以蒙层压不到它：弹层开着时导航照样亮着、照样能点，换页就在它上面完成，弹层内部不再重复一套页签。
这条导航只占导航那一条的高度（不铺满整屏），压不住弹层里其它卡片的点击。

- **双向可用**：再点一次当前这一页的页签 = 收起弹层回应用列表（`OpenPage()` 里 `target == page` 就换成 `Page.Home`），
  不会出现「点了没反应」；
- **一层层往回退**：`LauncherUI.Home.cs` 的 `GoBack()`——详情卡开着先关详情卡，在本机应用先回设置页，其它子页回应用列表，已经在首页就不动；键盘 `ESC` / `退格` 走同一条路；
- **键盘 1 / 2 / 3** 直换页（应用 / 我的时长 / 设置）：头显里是手柄点页签，这条留给接了键盘的机器和 PC 模拟；
- **回桌面是动作不是页面**：它排在分隔线右边，底色更淡、不参与选中态，免得被当成「当前页」；
- **换页从头看起**：`RebuildPage()` 末尾把 `pageScroll.verticalNormalizedPosition` 拉回顶部，上一滚停的位置不会串页；
- **选中态当场生效**：`pico/Assets/Scripts/UI/UiCard.cs` 里页签的选中底色原来是 `MoveTowards` 慢慢过渡、
  而且要等下一帧 `Update()` 才上色，换页那一帧拍出来还是上一页的选中态（无头抓图就是换页同帧抓的，正好拍个正着）。
  现在 `Pinned` 赋值当场 `Apply()`（值没变就不重复上色），底色不再渐变，只有悬停提亮留着渐变——
  「你现在在哪一页」这种事不该有半秒的模糊；
- **弹层开着就收掉首页那一层**：`OpenPage()` 里 `mainLayer.SetActive(target == Page.Home)`。
  以前弹层只盖住首页大半，面板上沿会露出半行「VR 学习启动器」，像界面没对齐在漏影；
  现在弹层期间只剩「暗底 + 面板 + 底部导航」三层。回首页时内容照常由 `Rebuild()` 重画，不用额外补；
- **列表被裁时给提示**：内容比列表高出一截，弹层列表底部才浮出「下面还有 · 往前推滑一下」的小胶囊（`UpdateScrollHint()`），
  矮于一屏的页不显示——戴着头显没人教「能滑」，看不见的卡片就等于没有。

### 功能性的都在设置页
首页不再出现「本机应用 / 管控模式 / 越权次数 / 后台地址」，页签也只剩三张（本机应用收进设置页，不占页签位）。
`pico/Assets/Scripts/UI/LauncherUI.Pages.cs` 的 `RebuildSettings()` 里排了：
统计三张（学生 / 这台头显+配对码 / 今日时长）→ **本机应用卡（点它才进 `Page.Local`）+ 管控模式卡** →
后台地址卡 → 本机信息卡（序列号 / 配对码）→ 权限卡 + 操作卡（清令牌、退出）→ 日志卡，右上角另给「刷新清单」「重扫本机」两个动作卡。
`Page.Local` 和 `LocalRowCount` 都保留，自动化入口 `ShowLocalPanel()` 照旧能直接跳（无头自检仍打印「本机应用」页行数）。

### 点卡片会发生什么
- 应用卡正文：能跑且已装 → 直接进；其余情况 → 打开详情卡看原因（不会静默失败）。
- 卡片右下角的动作卡才是真的执行：`进入` / `结束` / `为什么` / `详情`，标签按状态自动变。
- **只有后台设了每日上限才算时长**：`policy.js` 在没有策略时把 `dailyMinutes` / `remainingMinutes` 下发成 `null`，
  端上解析成 `0`，所以一律先认 `dailyMinutes > 0` 再谈剩余时长（`Capped` / `Remaining`），没设上限显示「时间不限」，
  不会再被误判成「今天用完啦」而明明能点却只让「为什么」。
- 被挡住的原因一定写在卡片小字和详情卡里，toast 只作补充。

### 手柄怎么点卡片
`XrPointerDriver` 把头显手柄射线接进 uGUI：优先读 `pointerPosition/pointerRotation`（指哪打哪），没有就退回 `devicePosition/deviceRotation`；
射线画成 `LineRenderer` + 命中光点，命中处自动缩短；再把射线与画布平面求交、换算成屏幕坐标喂给 `GraphicRaycaster`，
派发 `pointerEnter / pointerDown / drag / pointerUp`，所以卡片悬停、按钮点击、弹层滚动用的是同一套事件。扳机按下期间由这只手独占。
编辑器里没有 XR 手柄，整帧空转，鼠标继续走 `StandaloneInputModule`（PC 模拟照旧能点）。
卡片反馈在 `pico/Assets/Scripts/UI/UiCard.cs`：提亮背景、左侧圆角色条 12→18px、底部亮起高亮线、整卡放大 2%；选中态用更艳的 `pinnedColor` 常驻。

## 十三、上课（课堂）：看画面、当堂定人、记录算到学生头上
这是最容易搞错的一层关系，写死在这里：**设备和学生没有永久关系**。「VR 头显 03 属于谁」这个问题不该有答案，
只有在上一节课的时候才存在「这节课谁坐 03」。所以：

- 设备页 / 学生页都不再有「绑定」按钮；`PATCH /devices/:id` 收到 `studentId` 直接 400，把老师引到「上课」页；
- 「谁在用这台」只来自正在上的那节课的当堂分配；
- **使用记录算给学生**：`usage_events` / `violations` 在入库时同时写 `student_id` 和 `lesson_id`，
  值取自当堂分配。没上课时的记录只有设备没有学生，这是对的，不猜。

### 一节课的数据
`lessons`（课程名 / 班级 / 老师 / active|ended / 起止时间 / 备注 / 整节课的应用白名单）
+ `lesson_devices`（这节课里的每台头显；`student_id` 是**当堂**使用者，`app_keys` 是这台单独收窄的清单）
+ `device_screens`（每台最新一帧的元数据，图片落在 `server/data/screens/device-<id>.jpg`）。

四条硬规则（都在 `server/src/lesson.js` 里 `throw new HttpError(400, 中文)`）：
1. 一个老师同一时间只能有一节正在上的课——「《X》还没下课，先下课再开新课」；
2. 一台头显只能在一节正在上的课里——开课和加台都会校验，被占时提示是哪节课占的；
3. 一个学生在一节课里只能占一台头显——「陈嘉禾 已经在用「VR 头显 01」，先把他从那台上换下来」；
4. 下课之后不能再换人（换人已过滤到只剩 `status=active` 的课），但**历史记录一条都不动**。

两条清单规则：`lesson_devices.app_keys` **留空 = 跟随整节课**（开课和中途加台都是留空，所以老师后改整节课的清单它们自动跟着变），
单独给某台定了就只按那台的；整节课的 `lessons.app_keys` 留空则等于跟后台全局清单一致。
「单台清空」恢复的是跟随整节课，**不是变成这台不限**——`server/src/lesson.js` 里 `parseKeys(ld.app_keys) ?? parseKeys(l.app_keys)` 就是为这件事写的，
`api-test.mjs` 有两条断言钉着。另外下课只撤回当堂分配，
上课记录和画面统计永久保留，学生页的「最近一节课」就是从这里来的。

### 网页「上课」页（老师看什么、能干什么）
- **没上课时**：开课表单（课程名、班级、备注 + 勾头显 + 勾应用，全不勾 = 跟后台清单一致）＋「最近上的课」列表；
- **上课中**：顶部一栏课程信息（已上多久、几台定了人、在线几台、累计时长、几个学生有记录）+ 刷新/下课；
  中间是**画面墙**，每台一张实时画面 + 在线/电量 + 使用者下拉 + 「本机限定 N 个：…」+ 本机时长/画面/心跳新鲜度；
  下面是**课堂记录表**（学生 × 头显 × 应用 × 打开次数 × 时长 × 最近时间）。
- 画面用 `<img src="/api/v1/devices/:id/screen?ts=…">` 每 2 秒换一次地址，`ts` 变了才重新拉；
  没图时 `#view` 捕获 `error` 事件，把破图标换成「等头显传画面…／这台离线了，没画面」；
  计时和画面墙由每 2 秒的定时器局部刷，不整页重渲染，正在填的输入框不会被吞（整页自动刷新只在总览/设备/上课页做，且输入中跳过）。
- 总览加「正在上课」面板和「进课堂」按钮；设备页列名改「本节课使用者」；学生页改「这节课在用」+「最近一节课」。

### 头显端配合（`pico/`）
- `pico/Assets/Scripts/Core/ScreenStreamer.cs`：`WaitForEndOfFrame` 之后抓画面。取画面统一走主相机离屏渲染
  （`Camera.Render()` 到临时 RenderTexture 再 `ReadPixels`）——启动器界面就是这台相机画的，编辑器、真机、XR 是同一条代码路径；
  场景里取不到相机才退回 `Graphics.Blit(null, rt)` 拷后台缓冲。长边压到 480（超 600 KB 再降到 320）编码成 PNG。
  **这版 Unity（2022.3）没有 `Texture2D.EncodeToJpeg`**（Unity 6 才有），所以统一 `EncodeToPNG`，
  超过 600 KB 就降到长边 320 重编码；抓不到只回原因，绝不打断启动器主循环。
- `pico/Assets/Scripts/Core/LauncherBootstrap.cs` 的 `ScreenLoop()`：只在 `manifest.lesson.screen.enabled` 为真时抓，
  间隔按后台给的 `intervalMs`（响应里的新值会即时纠偏），失败按 4 倍间隔退避；没上课完全不耗电。
- `pico/Assets/Scripts/UI/LauncherUI.Home.cs`：顶栏副标题在上课时变成课堂横幅
  「上课中《课程》· 班级 · 已上 N 分 · 画面回传中」，学生卡换成「上课中 · 使用者」，时长卡那行显示画面进度；
  课堂清单外应用由后台直接标 `allowed=false` + 中文原因，端上不用另写一套判断。
- 开课/下课/换人会在启动器日志里各写一条（`AnnounceLesson`），学生不用猜为什么应用突然变灰了。

### 模拟头显
`node scripts/mock-pico.mjs --serial PICO-4U-A1B2C3 --rounds 400 --interval 6` 会登记→拉清单→传画面→心跳→报时长，

## 十四、按 IP 找头显（后台反过来敲门，新机器不用先配对）
原来的接入路径只有一条：头显先连上后台（填后台地址或拿配对码登记），后台才认识它。
机房第一次铺机器、或者头显里填错了后台地址时，老师对着一台已经开机的头显没辙，只能走过去握手柄。
这条路径反过来：**老师只要知道头显的 IP，后台主动去问它「你是谁、装着什么」，问到就直接收进来。**

### 问话口契约（头显开在 8790）
`pico/Assets/Scripts/Core/IdentityServer.cs`：`HttpListener` 只答两条路由，其余一律 404。
- `GET /v1/identity`（`GET /` 同样答，方便浏览器直接点开确认），应答体是
  `{ serial, name, model, launcherVersion, battery, foregroundApp, ip, serverBaseUrl, backendOnline, backendError,
     apps:[{packageName,label,version,isVr,isSystem}] }`。
  后三个是这台启动器**正在连哪个后台、连上没连上**：老师收编完却一直看见「离线」，八成就是这里指着打包时写死的占位地址
  （`http://192.168.1.100:8787`），网页那一栏直接把它摆出来，不用再靠猜。
- `POST /v1/config` `{serverBaseUrl:"http://192.168.31.20:8787"}`：后台把自己的地址**推**过来，省掉戴着头显敲 IP。
  HTTP 线程只校验（必须带 `http://` 和端口）并记进 `pendingBackend`，改配置和重连回主线程做——
  `LauncherBootstrap.Update()` 取一次清一次，复用现成的 `ApplyServerUrl()`（清 token、重新登记）。
  地址不对回 400 + 中文说明；成功回 `{serverBaseUrl, applied:true, changed}`。
- HTTP 线程**只读主线程发布的快照**：`LauncherBootstrap.PublishIdentity()` 在 `Start()` 和每次 `Notify()` 时
  换掉一个 `volatile` 引用，子线程从不碰 `SystemInfo` / `LocalApps` 这些 Unity API；JSON 也是手写（`Quote()` 转义），
  因为 `JsonUtility` 同样不许在子线程用。
- 绑定按 `+ → * → 0.0.0.0 → 127.0.0.1` 挨个试，哪个平台让绑哪个就绑哪个，全失败也只是这个问话口不开，启动器照常跑。
- 电量读不到时报 `null` 而不是 0，免得后台显示成「0%」骗老师去充电。
- 启动时写一行 `IdentityLine`：开着没、网页里该填哪个地址、绑在哪个范围（全网卡还是只对自己）、答过几次、清单里几个应用，
  例如「开着 · 网页里填 192.168.31.198:8790（监听在全网卡）· 已答 3 次｜清单里 8 个应用」。
  这行同时出现在「设置 → 日志卡」和**「首页 → 本机信息卡」最后一行**（「按 IP 登记这台：…」），
  老师站着看一眼就能把地址抄进网页，不用翻日志。外面那台电脑敲不动时先看这行——绑成 `127.0.0.1` 就说明全网卡没抢到。
- 地址取 `Dns.GetHostAddresses(Dns.GetHostName())` 里第一个非回环 IPv4，启动时算一次写进 `Address`，
  同时作为应答体的 `ip` 返回——头显自己报的地址比后台从连接上看到的更直观（多网卡时以第一个非回环为准）。
- `OnDestroy` 里 `Dispose()`，退出播放模式不留占着 8790 的后台线程。

### 后台（`server/src/discovery.js` + 两条接口）
| 接口 | 干什么 |
| --- | --- |
| `POST /api/v1/devices/discover` | 问一台或一整段。`{target}` 认 `192.168.1.20`、`192.168.1.20:8790`、网段前缀 `192.168.1`、`192.168.1:8790` |
| `POST /api/v1/devices/discover/adopt` | 把问到的这台收进后台，顺手把它报的应用清单落库 |
| `POST /api/v1/devices/:id/backend` | 后台把自己地址推给这台（`configureDeviceHost` → `POST /v1/config`）；收编时自动做，之后老师随时能在设备页再点一次 |

- 单台超时 1.2 秒；扫网段每个地址 0.7 秒、并发 32 路，扫满 `.1~.254` 大约 6 秒。
- **问不到不算错**：HTTP 200 + `{ok:false, reason:"…"}`，网页就地显示中文原因；
  只有填得根本不像 IP 才 400（「不像 IP：写 192.168.1.20，或网段前缀 192.168.1」）。
  原因分三种写法，都带下一步（见下面「问不到时怎么查」），不再是干巴巴一句「拒了连接」。
- **收编前重新问一次**，不信网页带上来的那份快照：网页可能开了好几分钟，而且不能允许网页伪造一份应用清单直接入库。
- 落库跟头显自己上报走**同一个** `applyDeviceApps()`（`syncDeviceApps` 现在也调它），两条路一条账：
  报来的新应用进目录、标 `source='device'`、类别「未分类」、图标 `🎮`、默认不上架等老师确认；系统应用（桌面、商店）不进目录。
  （图标不给 `🆕`：扫描天天都在做，摆个「新」字会让学生以为这应用刚装上来；老库里的 `🆕` 由 `server/src/db.js` 一次性换成 `🎮`。）
- 序列号已登记的只补型号、启动器版本、IP、`probe_port`、`last_probe_at`，**不动老师起的名字**，也不动 `last_seen`
  ——在线与否继续只由心跳决定，别让「问得到」冒充「在线」。新收编的那台同样**不写 `last_seen`**：
  以前一收编就算在线，三分钟后自己掉成离线，老师完全猜不到是后台地址还没推过去。
- **收编成功后立刻把后台地址推给它**（`configureDeviceHost`），推没推成回给网页并记审计
  （`device.backend` / `device.backend.fail`）：不推的话这一步就得有人戴着头显在「设置」里敲 IP，
  而启动器的默认地址是打包时写死的 `http://192.168.1.100:8787`，不改这台永远连不上。
- 后台报自己的地址（`server/src/server.js` 的 `publicBaseUrl`）：`PUBLIC_BASE_URL` 环境变量优先 →
  请求头 `Host` 不是环回就照抄（老师用局域网 IP 打开网页时推的就是这个）→ 否则 `http://<本机局域网 IPv4>:<端口>`。
- `devices` 表加 `ip` / `last_probe_at` / `probe_port` 三列（`PRAGMA table_info` + 条件 `ALTER TABLE`，老库直接升级），
  设备列表把问到的地址显示出来；`probe_port` 让「让它连上后台」不必永远瞎敲 8790；
  审计动作 `device.discover` / `device.adopt` / `device.adopt.refresh` / `device.backend`。

### 老师网页（设备页「按 IP 找头显」面板）
一个输入框 + 「开始找」，结果表列 名称 / 序列号 / 型号版本 / 地址 /**它正在连的后台** / 应用数 / 电量 /「已登记 #N」或「还没这台」+ 收编按钮。
结果存在 `state.discovery` 里、只重画结果区，免得 8 秒一次的自动刷新把结果冲掉；点收编 → toast → 重新问一遍刷新状态 → 整表刷新；
收编时后台地址没推过去会**再弹一条错**（不然下一步就是「怎么显示离线」）。

离线那行不再只有一个「离线」徽章：`offlineReason` 分两种写法，各带处置——
从没心跳过的说「启动器还不知道后台地址」并给一个「让它连上后台」按钮（`POST /devices/:id/backend`），
心跳过又不吭声的说「多半是头显睡了」并提示戴上头显打开启动器；有最后心跳时间的顺带显示「最后心跳 X 分钟前」。

全局兜了一条 `unhandledrejection` → toast：以前 async 点击回调里抛异常就是「点了没反应」，
老师根本不知道后台回了 404（「雪山滑雪删不掉」那次就是这么被吞掉的）。

### 问不到时怎么查（「这台 IP 拒了连接」到底是什么意思）
这台 IP 应答了个 TCP RST，意思是**那个端口上压根没人监听**——不是网络不通，也不是密码错。
`failReason()` 按三种情况分开说，并且**填的如果是后台自己这台电脑，直接把话点破**：

| 现象 | 后台现在怎么说 | 真正要做的 |
| --- | --- | --- |
| 端口没人听（ECONNREFUSED） | 「这台 IP 拒了连接（IP:8790 没人监听）：启动器没在跑，或者它太旧没开问话口……」；填的是本机时再补一句「（127.0.0.1 就是跑后台的这台电脑：用 Unity 播放模式跑启动器，或者先起一台模拟头显 `node scripts/mock-pico.mjs --serve --respond-port 8790`）」 | 启动器得**正在跑**：PC 模拟＝Unity 进播放模式；真头显＝把启动器打开停在那儿别退回桌面 |
| 问了没回（超时） | 「问了没回（8790 口没应答，2600 毫秒就放弃了）：确认 X 是这台头显现在的 IP、启动器开着，而且它和后台在同一个网段」 | IP 抄错了 / 头显休眠了 / 不在同一个网段（AP 隔离也会这样）。单台超时从 1200 提到 **2600 毫秒**：真头显 Wi-Fi 省电模式会把唤醒后的第一个请求拖到一秒多，1200 在电脑上好使、到真机上就成了「问了没回」，老师只能反复点（扫整段仍按 700 毫秒，量在那儿） |
| 它回了非 200 | 「它回了 HTTP 404，不像启动器的问话口（它只答 `GET /v1/identity`）：`IP:8790` 上跑的可能是别的服务，或者这台头显的启动器版本太旧」 | 端口被别的服务占了，或者装的确实是旧包 |

**本机实测过的两个真实原因**（2026-10-24，就是这个报错）：
- PC 模拟：`lsof -nP -iTCP:8790 -sTCP:LISTEN` 是空的 → Unity 播放模式当时根本没开，报错完全正确。
  补一轮模拟头显就通：`node scripts/mock-pico.mjs --serve --respond-port 8790`，
  之后网页里填 `127.0.0.1` 或本机局域网 IP（现在是 `192.168.31.198`）都问得到；
  `curl http://<IP>:8790/v1/identity` 是最快的单点验证，不用开网页。
- 真头显（**这轮已修**）：当时那份 `Build/Android/VR-Launcher.apk` 是 10-24 **17:58** 打的，而问话口的 `IdentityServer.cs`
  是 **22:33** 才有的——包里的启动器根本不开 8790，网页填什么都必然「拒了连接」。
  10-25 已用团结引擎重打（IL2CPP + ARM64，156 秒，20.5 MB），`node scripts/apk-check.mjs` 实测
  `v1/identity`、`这儿只有 GET`、`本机信息卡`、`不在允许清单里` 全在 `global-metadata.dat` 里，`--strict` 退出码 0。
  真机复验：`~/Library/Android/sdk/platform-tools/adb install -r Build/Android/VR-Launcher.apk`，
  启动器停在主界面时从 PC 敲 `curl http://<头显IP>:8790/v1/identity`，出 JSON 就是通了。
- **搜标记只能搜字符串字面量**（`apk-check.mjs` 的标记全按这条挑）：原先把端口 `8790` 也当标记一起搜，
  它在代码里是 `public const int DefaultPort`，编进元数据的是数字不是文字，**永远搜不到**；
  拿「`8790` 搜不到」当包旧的证据是误判，真证据是 `v1/identity` 缺失。同理包内条目时间被 Android 归一成 1981，文件 mtime 又会随复制改动——**日期都不能当新旧证据，只认标记**。
- **旧包不等于接不进来**：那台头显照旧走「登记头显」手填序列号（启动器「设置」里把后台地址填对），
  心跳、白名单管控、时长统计、上课分配全都照常，只是不能按 IP 认领它。
- `bash scripts/stop.sh` 现在会连同 `--serve` 挂着的模拟头显一起停，免得它一直在后台上报时长。
- 答话体里的 `ip` 报的是**被敲的那个地址**（`req.socket.localAddress` / `context.Request.LocalEndPoint`），
  所以从别的电脑敲局域网 IP 时，回的不是 `127.0.0.1`。

### 收编成功了却一直「离线」、应用允许了却跑不了
这两个是同一串因果，2026-10-25 在真机 PICO 4（`PICO-22A118BA79514743`）上撞齐了，逐个说清：

1. **收编 ≠ 上线**。收编只是后台单方面认识了这台；它自己还在往打包时写死的 `http://192.168.1.100:8787` 心跳。
   现在收编那一步顺手推一次地址（`POST /v1/config`），设备页离线行也留了「让它连上后台」按钮。
   手填也行：头显「设置 → 后台地址」填 `http://<PC 局域网 IP>:8787`（现在这台是 `192.168.31.198`）。
   旧包不认 `/v1/config`（404），后台照实说「多半太旧，请戴上头显手填」，不会假装成功。
2. **启动器别一失焦就停**。`Application.runInBackground = true`：学生点开别的 VR 应用、或 PC 模拟时一切换窗口，
   心跳和前台计时不再整个停住（这是真机显示离线最常见的原因之一）；`OnApplicationPause(false)` 回前台立刻重新要一份清单，
   老师刚放开的应用不用等下一次 45 秒轮询。
   还有 `Screen.sleepTimeout = SleepTimeout.NeverSleep`：头显一入睡，心跳和 8790 问话口会**一起**停，
   表现为「后台显示离线 + 网页按 IP 找它说问了没回」，两头都查不出原因（真机就是这么撞上的：
   09:09 还答过 `POST /v1/config`，09:12 起连着二十多次全部超时）。代价是费点电，管控用的启动器认这个账。
3. **允许了仍跑不了，看是不是被课上拦了**。白名单模式下正在上的那节课如果限死了应用清单
   （`lesson_devices.app_keys ?? lessons.app_keys`），课开在允许之前就有这个现象：`buildManifest` 里 `inLesson` 为假，
   照样拦回桌面，原因写「《课程名》这节课没安排这个应用」。现在存策略时就回 `notice`，网页 toast 出来，处置是去「上课」页把它勾进这节课。
4. **课上的清单跟着课走，别改完就以为完了**：改的是整节课还是只那台头显，两处都能改（`POST /lessons/:id/apps` 给不给 `deviceId`），
   老师改完全屏刷新，头显下次心跳生效。
5. **明文 HTTP 被系统挡掉：收编、推地址、日志全都说自己成功了，心跳却一次没发出去**。
   `targetSdk 33` 起 Android **默认禁止明文 HTTP**，而机房后台是 `http://局域网IP:8787`，没证书。
   于是启动器每个 `http://` 请求都被平台挡在应用里（`CLEARTEXT communication to 192.168.31.198 not permitted`），
   表现却像网络问题：后台一直显示离线、日志里失败原因是空的（`失败：0 `）、而 PC 去敲它的 8790 反倒答得好好的
   ——**入站不归这条策略管**，所以「按 IP 找头显」通、心跳全灭，最容易把人带偏。
   修法就一行：`pico/Assets/Plugins/Android/AndroidManifest.xml` 的 `<application>` 上加
   `android:usesCleartextTraffic="true"`。验它在不在包里（不用装机）：
   `~/Library/Android/sdk/build-tools/34.0.0/aapt dump xmltree Build/Android/VR-Launcher.apk AndroidManifest.xml | rg -i cleartext`
   （注意 aapt 的语法是 `dump xmltree <apk> <文件>`，不是 `--file`）。
   配套改了两处：`ApiClient` 在后台一个字都没回时改取 `request.error` 当错误文案，
   头显首页才会写「连不上后台：CLEARTEXT communication …」而不是冷冰冰的「失败：0 」；
   网页「按 IP 找头显」面板顶上多一行「这台后台的地址是 …」＋复制按钮
   （填错地址是另一半的锅；`http://局域网IP` 不是安全上下文，clipboard 失败要退回 `execCommand`）。
6. **同一个明文 HTTP，在 PC 模拟里是另一种死法，而且更难查**。Android 认的是上面那条
   `usesCleartextTraffic`；编辑器和 PC 播放器认的是**另一个开关**——
   Project 设置 → Other Settings → Allow downloads over HTTP（`ProjectSettings.asset` 里的 `insecureHttpOption`，
   默认 `0`＝不允许）。它不允许时不是返回失败，而是**当场抛异常**：
   `InvalidOperationException: Insecure connection not allowed`（`ApiClient.cs` 里 `SendWebRequest()` 那一行）。
   要命的是这个异常在协程里，会把**启动器主循环整个打断**：之后心跳、清单、课堂状态一个都不发，
   连失败次数都攒不起来，所以「自动找后台」也不会触发。
   现象就是网页那句「这台 IP 拒了连接（8790 口没应答）」＋设备显示离线，而**真机一点事没有**，
   最容易误判成网络或防火墙问题（本轮就是这样，PC 模拟里「后台清单」「课堂状态」两步稳定红）。
   修法两处：
   ① `ProjectBootstrapper.ConfigureAndroid()` 里写 `PlayerSettings.insecureHttpOption = InsecureHttpOption.AlwaysAllowed`，
   同时把 `pico/ProjectSettings/ProjectSettings.asset` 直接改成 `insecureHttpOption: 2`——
   只改引导函数的话，不重跑 `unity.sh setup` 工程设置里还是旧值，等于没改；
   ② `ApiClient.SendSafely()` 把 `request.SendWebRequest()` 可能抛的异常接住，转成中文说明
   （「系统不让走明文 HTTP，去 Project 设置 → Other Settings 改成 Always allowed」）。
   迭代器里 `yield` 不能待在 try/catch 里，所以拆了个返回 `SendOutcome` 的小方法，
   画面上传那条 `UploadScreen` 同样兜住——**任何后台请求都不许再掀翻主循环**。
   排查顺序记一下：PC 模拟连不上后台，先去 `/tmp/pico_verify.log` 找
   `Insecure connection not allowed`，别一上来就猜端口和防火墙。
7. **网页上那行「该改成 `http://127.0.0.1:8787`」是错的建议**。它是拿 `location.origin` 拼的——
   老师在 PC 浏览器里打开后台，地址栏自然是 127.0.0.1，可这串地址是**给头显填的**，
   头显照抄就等于连自己，永远连不上。现在改成后台自己报：`GET /api/v1/hello` 和 `GET /api/v1/devices`
   都返回 `baseUrl`（走 127.0.0.1 访问时也回局域网 IP），面板、复制按钮、「该改成」三处统一读它。

## 十五、头显自己找后台（`pico/Assets/Scripts/Core/BackendFinder.cs`）

### 为什么要第三条路
让头显知道后台在哪，原先只有两条路，两条都会「看着没错但连不上」：

1. **打包时写死的占位地址**（`LauncherConfig.DefaultServer` = `http://192.168.1.100:8787`）。机房基本不是这个网段，
   装上就报「连不上这个后台」，得戴着头显敲 IP 改一次。
2. **老师在网页上把地址推过去**（`POST /v1/config`）。这条要求**此刻**这台头显醒着、启动器停在前台、8790 有人听——
   头显一打盹或者 Wi-Fi 省电，推送就超时，而老师看到的只是「没推过去」。

所以补第三条：**头显自己扫**。读本机 IP → 顺着它所在的 C 段挨个敲 8787 → 谁答 `product=vr-suite` 就认谁。
方向反过来了，不再依赖「PC 能找到头显」这件事，上面两个坑一起绕过。

### 契约与实现
- 敲 `GET /api/v1/hello`（免登录），**认 `product` 暗号不认端口号**：8787 上跑着别的服务时不会认错后台；
  采纳的地址优先用应答里的 `baseUrl`（后台自己报的最不容易拼错），报不出来才退回刚敲的那个。
- 网卡来自 `NetworkInterface.GetAllNetworkInterfaces()`，只认内网段（10 / 172 / 192），
  跳过环回和 169.254（拿不到 DHCP 时自己凑的地址）；同时连了有线和 Wi-Fi 就两段都扫。
. `.1` 排最前（机房里老师的电脑常挂在网关上，先撞到能省两秒），其余 `.2~.254`；
  并发 64 路，连接只等 350 毫秒、连上之后读回话给 700 毫秒。
  扫描耗时约等于「地址数 ÷ 并发 × 连接超时」：**绝大多数地址根本不存在，连它只能干等到超时**，
  所以决定快慢的是连接超时而不是应用层。实测这台 Mac 有两块网卡（`192.168.31` + `172.47.68`，508 个地址），
  按最早的 40 路 / 700 毫秒要 9 秒才扫完，改成 64 路 / 350 毫秒之后三秒内；真头显一般一块网卡，一秒多
- 传输用**裸 socket 发一句 GET**，不用 `HttpWebRequest` 也不用 `UnityWebRequest`：
  后者只能在主线程起（扫描在独立线程上），前者的类名在这个工程里和 `UnityEngine.Networking` 撞名，
  编译只报「UnityEngine.Networking 里没有 HttpWebRequest」，看得人一头雾水。
  读回开头几百字节就够（后台这一句很短），凑齐头和 `{` 立刻收工，不等对方关连接。

### 什么时候扫、扫到之后怎么办
- 自动：连着**两轮**心跳/清单都失败才扫（刚启动那几轮不必惊动整个网段），之后**越扫不到扫得越稀**
  （60 秒起步，翻倍到 300 秒封顶），后台真关机时也不会把机房网络敲满。
- 手动：头显「设置 → 后台地址卡 → 自动找后台」，马上扫一轮，不等失败攒够。
- 三种结果分开处置，日志（`Note`）和设置页那一行都照着说：
  ① 找到**别的**地址 → 直接 `ApplyServerUrl` 换过去重新登记；
  ② 找到的**就是现在这个** → 地址没错，问题在路上（不在同一个 Wi-Fi、路由器开了客户端隔离），说清这个就不必再改地址；
  ③ **一个没找到** → 多半是后台那台电脑没在跑（`bash scripts/dev.sh`）或者两头根本不同网段，并给出下一轮扫描的时间。

### 怎么验
- `bash scripts/test.sh unity` 的第 6、7 步：真起一轮扫描，验它**扫得完**（线程收尾没数错、没被哪个地址吊住）、
  结论**回得到主线程**，并且扫到的那个地址确实答 `vr-suite`。这一步故意放在最后——它可能顺手把后台地址改掉。
- 手工单点：`curl http://<头显或本机局域网 IP>:8787/api/v1/hello`，出 `{"product":"vr-suite",...}` 就说明这一片里能被扫到。
- 真机上想立刻看效果：装上新的 `~/Desktop/VR-Launcher.apk`，戴上头显停在主界面，
  「设置 → 后台地址」能看到当前地址、下面一行写着自动扫描的结果；日志里会出现「自动找到了后台 …，换过去重新登记」。

## 十六、2026-10-25 又一轮：把「等半天没反应」和「看着在线其实睡了」按下去

这轮都是从真实状态里翻出来的（真库里那节《111》就是空壳课），四条都是能复算的账，不是凭感觉调参数。

### 1. 老师改完多久到学生：清单版本号（`rev`）
原先头显只按 45 秒一次定时拉清单，心跳 10 秒一次却不带任何状态变化信息，
于是「老师点了允许」到「学生能打开」最坏要等 45 秒；上课点名、下课、锁定同理。
现在加了一个只增不减的计数器（`state` 表里一行 `manifest_rev`）：

- **只有老师动手才 +1**：`server/src/server.js` 在所有「需要登录 + 非 GET」的接口出口统一 `bumpManifestRev()`。
  一个地方收口，不用在几十个处理函数里各补一句；头显自己上报的那批（心跳、时长、画面、扫描、ack）都是 `public`，
  不参与递增——否则心跳自己把版本号推高，头显每 10 秒白拉一次清单。
- **`/manifest` 和 `/devices/heartbeat` 都回 `rev`**。头显在 `LauncherBootstrap` 里记住手里这份清单是第几版，
  心跳发现对不上就当场 `RefreshManifest()`（日志：「后台的安排变了（第 34 → 第 35 版），重新拉一份清单」）。
- 老后台不回 `rev`（＝0）时按「没变」处理，行为跟加这个字段之前一模一样，**不会逼着两头一起升级**。
- 定时轮询留作兜底，从 45 秒改成 30 秒（`LauncherConfig.ManifestSeconds`）：万一 rev 那条路某一轮没走通，最迟 30 秒也对齐。

净效果：**常规路径 10 秒内到**，最坏 30 秒，网络开销基本没变（每 3 个心跳拉一次清单，之前是每 4.5 个）。

### 2. 「在线」不再骗人：窗口 3 分钟 → 45 秒
心跳本来就是 10 秒一次，可 `ONLINE_WINDOW_MS` 写的是 3 分钟——头显睡了、被学生划掉了，
网页上还挂着将近三分钟「在线」。最坑的是「让 N 台在线头显重新扫描」照着这个数点，点完一台都不动。
现在 `server/src/policy.js:5` 是 45 秒（＝4 个多心跳没到），提示文案从同一个常量算出来（「超过 45 秒没有心跳」），不会再出现两处说法不一致。
`offlineReason` 那两条中文说明（从没配对／多半睡了）本来就是为「别只写离线」加的，这里跟着一起对得上。

### 3. 空壳课：开着却一台头显都没有
真库里的 lesson 2《111》就是这种：`status=active`，`lesson_devices` 里一行都没有，`app_keys=["browser-1"]`。
排查发现成因不是开课没选头显（`POST /lessons` 本来就拦着「至少选一台」），
而是**课上着上着老师把那台头显从设备页删了**——`deleteDevice` 顺手 `DELETE FROM lesson_devices`，课就空了，却还挂着「上课中」，
而头显那边压根不受这节课管（`activeLessonForDevice` 要求这台有座位），于是「允许了却跑不了 / 跑了却没记到学生头上」。
三处补上：
- `DELETE /devices/:id` 删的时候回一句 `notice`：「这台正在《X》这节课里，已一并从课上移出；那节课现在需要重新指定头显」，网页 toast 直接显示；
- `/dashboard` 的「需要关注」多一类 `type:"lesson"`：「这节课开着但一台头显都没指定，头显那边不受它管」；
- **「上课」页原来根本没有补加头显的入口**（接口 `POST /lessons/:id/devices` 一直有，就是没接）：
  现在多一个「参加的头显」面板，列出没在课上的头显 + 「加进这节课」按钮；
  座位墙在 0 台时不再摆一块空墙，改成明说「这节课还没定头显：头显那边完全不受这节课管，时长也不会记到学生头上」。
- 顺带把 `addLessonDevice` 的审计日志补上操作人（原先写死 `NULL`，日志里看不出是谁加的）。

### 4. 头显被杀掉时那段时长不再凭空消失
`UsageRecorder` 断网时本来就落盘，但**正在计时的哪一段**（`endedAt=0`）在恢复时会被原样塞回队列，
报上去就是个 0 秒事件——真实那段全丢。现在读盘时把这种没结尾的段补算成「到本次启动为止」，
封顶 2 小时（宁可少算，也别算出一个 20 小时的学生），并在日志里说「补算了 N 段没结算的时长」。
顺手给待上报队列加了 2000 条上限（`Trim()`）：断网断一周也不会把 `usage_queue.json` 撑到几百 MB，撑不下丢最老的并说明。

接口 **181/181**、网页 **66/66**、Unity 无头自检 **7 步全绿**（第 2 步多一条断言：清单必须带版本号）。

## 十七、2026-10-25 再一轮：学生管理能用了，「带句话」不再是假动作

### 1. 学生名单：从「只能加和删」到真能管
原来的后台只有 `POST /students`（加）和 `PATCH /students/:id`（只认 `status` / `name`），
班级更是只有 `POST /classes`。实际用起来三件事压根办不了，而每一件都只能「删了重录」，
一删这个学生的时长记录就断成两段（`deleteStudent` 把 `usage_events.student_id` 置空）：

- **学号录错了改不了**——机房里手写名单再录进电脑，错一位就得重来；
- **学期中途转班改不了**——`class_id` 一旦写下就没接口能动；
- **班级不能改名也不能删**——建错一个字就永远挂在那儿。

现在（`server/src/api.js`）：

| 接口 | 新增能力 | 报错口径 |
| --- | --- | --- |
| `PATCH /students/:id` | `name` / `studentNo` / `classId`（`null`=未分班），返回 `changes[]` | 学号撞了会说是谁的：`学号 9001 已经是 自检甲 的了，换个学号再存`；班级不存在：`这个班级不存在，刷新一下页面再重新选` |
| `POST /students/bulk` | 整贴名单：一行一个，`学号 姓名 [班级]` 或 `姓名 学号` 都认（看第一段像不像数字），班级名没有的当场建班，学号已存在的行跳过不报错 | 返回 `created[] / skipped[{line,text,reason}] / newClasses[]`，一次上限 300 行 |
| `POST /classes` | 同名班拒绝（两个同名班，导入名单和按班配策略都说不清指谁） | `已经有叫「初三(2)班」的班了` |
| `PATCH /classes/:id` | 改名、改年级。策略跟的是班级 **id**，改名不用重配 | 撞名同样拒绝 |
| `DELETE /classes/:id` | 班里还有人先回 400 报人数；确认（`moveStudents:true`）后学生转未分班、`lessons/devices` 的班级引用清掉、这个班的 `policies` 一起删 | 「时长记录不丢」写进提示，也写进 `notice` |

`GET /classes` 顺手带上 `activeLessons`（这个班有没有正在上的课），删班前老师看得见。

网页「学生」页（`server/web/js/app.js`）重排成三块：**班级卡片**（人数/有没有开课 + 改名 + 删班）、
**加一个学生 + 整份名单贴进来**（左右两栏）、**名单**（搜索 + 班级筛选片 + 表格）。
姓名和学号就是行内输入框，改完 `change` 就提交；班级是行内下拉。
筛选片和搜索词存在 `state.students` 里，提交完不会因为重绘而丢掉老师正在看的那一段。
另外补了「累计时长」这一列——`listStudents()` 本来就算好了 `total_seconds`，页面一直没用。
上课页当堂点名的下拉里，**已停用**的学生会写明「点了这台会被锁住」：`policy.js` 的
`device_requires_lock` 本来就会因为学生 `status != active` 锁掉这台头显，
以前老师点了才知道，现在点之前就知道。

### 2. 真根因：路由层从来不读 DELETE 的请求体
`server/src/server.js` 原来写的是

```js
const raw = req.method === "GET" || req.method === "DELETE" ? Buffer.alloc(0) : await readRaw(req);
```

也就是说 `deleteStudent` / `deleteDevice` / `deleteApp` 这些处理函数拿到的 `body` **永远是空对象**。
`DELETE /classes/:id` 的 `moveStudents` 一加上就被静默丢掉，表现是「确认了还是删不掉」。
改成只有 GET 不读体（`readRaw` 对没体的请求直接给空 Buffer，行为不变）。
这类坑不在报错里，只在「参数怎么都不生效」里。

### 3. 「带句话」以前是个假动作
后台 `queueCommand` 早就支持 `type:"message"` 并把 `text` 存进 `commands.payload`，
但端上是 `case "message": break;`，而且 `CommandInfo` 连 `payload` 字段都没有（`JsonUtility` 按名字匹配，
没声明的字段直接丢）。合起来的效果：指令被 ack 掉、日志写着「已执行」、学生那边什么都没发生。

现在（`BackendModels.cs` + `LauncherBootstrap.cs` + `LauncherUI.Home.cs`）：
`CommandInfo` 加 `payload`（`CommandPayloadInfo.text`），收到话就 `ShowTeacherMessage()`，
**45 秒内**首页横幅那行小字换成「老师带话：……」，同时弹一次提示条（去重，不是一秒弹一次），
过期自动回到平时那句，不需要谁去关。`DescribeCommand` 也从「提示消息」改成「老师带话」。

网页设备页补了两个一直没入口的按钮：**「带句话」**（弹窗输一句话）和**「重新登记」**
（`restart` 指令同样早就支持：端上会结算时长、清令牌、重新登记）。

## 十八、2026-10-25 再一轮：明细看得见、停用不闷人、空清单不装断线

### 1. 真根因：`#view` 是常驻节点，监听器一路加，改一次名字发三份 PATCH
`index.html` 里的 `<section id="view">` 从头到尾就那一个，页面函数只换它的 `innerHTML`。
而 `students()` 里写的是 `el("view").addEventListener("change", ...)`——**每进一次学生页就往它身上多挂一个**，
进出三趟之后把姓名改一下，同一份 PATCH 连发三次、提示弹三条（后两次是空改，回 `changes: []`）。
全站扫了一遍，只有这一处往常驻节点上绑：其余 `el("add-student")`、`el("student-search")`
这些都是本次重绘新建的节点，绑了就跟着 innerHTML 一起换掉，不会累积。
改法是把它绑到本次新建的 `<tbody id="roster-body">` 上——两个行内控件（姓名/学号输入框、班级下拉）本来就都在 tbody 里。

### 2. 跟着踩到的坑：`toggle` 事件不冒泡
新加的「看明细」想收 `<details>` 的展开事件，绑在 tbody 上却一次都没收到，而且**一声错都不报**，
页面上永远是那句占位话。原因：`toggle` 不冒泡，`addEventListener` 默认收冒泡阶段，祖先压根听不见。
补上第三个参数（捕获阶段）就通了：

```js
el("roster-body").addEventListener("toggle", async (event) => { ... }, true);
```

这条是网页自检抓出来的（`viewHas("近 7 天共")` 超时），拿探针脚本直接看请求有没有发出去，一眼定位。

### 3. 停用中的学生被点名：这句提醒由后台说，不靠网页下拉框标小字
`device_requires_lock` 本来就认「课上那个学生 `status != active` 就锁掉这台」，
但 `assignStudent` 照收不误，网页只在点名下拉里标一句「已停用」——老师点完，头显锁着，还得自己猜为什么。
现在 `assignStudent` 的返回里带一句 `warning`，网页拿它当提示语（有 warning 就按失败语气弹）。
判断只写在后台一处，网页只是念出来。

### 4. 点名日志里的头显名字从来没写对过
`server/src/lesson.js` 的 `assignStudent` 查的是 `SELECT * FROM lesson_devices`，日志却读 `row.name`——
**这张表没有 `name` 这一列**，后面的 `?? 头显 #${deviceId}` 一直兜着底，日志永远是「改用 头显 #7」。
把 `devices` 一起 `JOIN` 出来读 `device_name`，翻日志才认得出是哪一台。

### 5. 下课之后还能改这节课的应用清单，改了谁也不看见
`setLessonApps` 原来不看课程状态：课都下了还把清单存回去，头显早就不按这节课的清单跑了。
现在直接回 400 并指路：「这节课已经下课了，清单就定稿了；要长期放开应用，去「头显应用」里配策略」。

### 6. 学生「看明细」：`GET /api/v1/students/:id/usage?days=N`
名单上原来只有「今日／累计」两个总数，老师真问的是**他跑了哪几个应用、各多久、在哪台、算哪节课**。
新接口 `apps[]` 按应用汇总（时长／次数／几台／最近一次），`sessions[]` 是最近 20 条原始记录（带设备名和课程名）。
网页把它做成姓名下面一个「看明细」，**点开谁才拉谁那一份**，不给整份名单每个人都先拉一遍。

### 7. 真根因：后台回「200 + 空清单」，头显报「连不上后台」
`RefreshManifest` 的成功条件写成 `result.apps.Length > 0`。老师在网页上把应用都停光、
或者这台还没扫出应用时，后台回的是 **200 + `apps: []`**（curl 实测），于是端上：

- 状态条写「连不上后台：拉取清单失败」，网页上这台却明明在线；
- `FailedRounds` 攒两回就开始满网段扫后台（`SearchAfterFailedRounds = 2`），白敲 254 个地址。

条件改成只看 `result != null && result.apps != null`，空清单算成功。
配套把「连上了但没安排」和「还没连上」在界面上分开：新增 `LauncherBootstrap.HasManifest`，
横幅标题走「后台还没安排能玩的应用」、小字说「应用可能都被老师停掉了」，不再让学生去翻后台地址；
卡片区的空提示同样分两岔。为自检另加 `LauncherUI.BannerTitle`（小字那行会被「老师带话」临时占用，标题不会）。
